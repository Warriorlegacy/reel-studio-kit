# Motion and channel research · 2026-11-15

## Production direction for the pilot

Use one visual conflict and one answer: two request cards collide over one 09:30 appointment slot; both appear available in an unsafe, uncoordinated flow; a stable slot-specific ID routes both through one Durable Object; an async storage reservation is protected; one request wins and the second sees BOOKED.

- Put the conflict on frame zero and make the first spoken words land within the first second.
- Build a compact mini-story: conflict → why it happens → one mechanism → payoff → a short loop to the opening.
- Reuse one slot card and two request lanes as visual characters. Animate only when the narration names a request, read, route, await, commit, or reject.
- Keep one main focal point, no more than two short labels at once, Hindi captions readable on a phone, and key text within platform safe areas.
- Use restrained UI sound effects under the Hindi voice. Avoid intro logos, dense code screenshots, unrelated motion, and generic neon graphics.
- End with a single comment ask. The same usable checklist is pasted into each platform's pinned first comment; it is not a local-file promise or a DM automation promise.
- Do not promise virality. Compare the first second, chose-to-view/swipe-away, average view duration, percentage viewed, saves/shares, comments, and subscriber/follower changes against this channel's own baseline.

## YouTube pivot plan

The user explicitly chose a Hindi-tech pivot for @cadetsingh. Keep the handle and old library. Bridge the old comedy/entertainment audience with relatable real-world tech conflicts rather than deleting unrelated older uploads.

Repeatable series:
1. **Tech ka real-life problem** — one familiar failure told as a short story.
2. **AI tool: one task, one limitation** — show a real result and one honest constraint.
3. **System in 30 seconds** — one animated systems idea and one payoff.

For each upload, keep the first visual and title promise aligned. Use YouTube Studio metrics to compare openings and formats; don't optimize raw views alone.
